## はじめに

Claude Codeは、プルリクエスト（PR）のドラフトが解除されたときにレビューします。すべてのセッションは、PRをドラフトとして作り、作業とセルフレビューを終えてからドラフトを解除します。

## 動機

問題が見つかった時点で、`main`のルールセットは`claude review`チェックを必須としていました。レビューはPRを開いたときだけ動いたので、チェックは最初のコミットに残り、その後のプッシュでPRはマージできなくなりました。`@claude review`で依頼したレビューも解決になりません。GitHubは、`issue_comment`による実行をデフォルトブランチに記録するからです。PR #45は、レビューが成功した後も、この理由で止まりました。

この変更が入ると、ドラフトの手順を終えたPRの先頭コミットに`claude review`チェックが付き、レビューは完成した作業を対象とします。

## 詳細設計

- **トリガー。** ワークフローは、`opened`と`reopened`に`ready_for_review`を加えます。プッシュでは、これまでどおりレビューを始めません。
- **ドラフトとボット。** GitHubは、スキップされたジョブを合格として扱います。そこで、ワークフローを起動する`pull_request`イベントでは必ずジョブを動かし、最初のステップが、ドラフトとボットのイベントで失敗します。人がドラフトを解除すると、新しい実行がその失敗を置き換えます。
- **コメント。** ドラフトにも`@claude review`とコメントできます。コメントによる実行は、スキップされた場合も`claude review (requested)`という名前になるので、必須チェックを満たすことも、上書きすることもありません。
- **セッション。** `AGENTS.md`のGitの節で、すべてのセッションに同じ手順を示します。
  1. 利用者にPRを頼まれたら、`gh pr create --draft`で作る。
  2. コミットはすべてドラフトにプッシュし、最後のコミットで`scripts/check.sh`を通す。
  3. 変更の大きさによらず、`.claude/review-contract.md`のコールドレビューをブランチの差分全体に行う。指摘をすべて直し、指摘がなくなるまで新しいレビュアーで繰り返す。対応しない指摘は、理由をPRの本文に書く。
  4. 設計の判断が必要な指摘があるとき、または3回目でも指摘が残るときは、ドラフトのまま利用者に確認する。
  5. `gh pr ready`を実行する。
- **後からの変更。** ドラフトを解除したPRを変更するセッションは、`gh pr ready --undo`を実行し、修正をすべてプッシュし、セルフレビューを繰り返してから、もう一度`gh pr ready`を実行します。この手順により、新しい先頭コミットのレビューが1回始まります。
- **提案用のスキル。** `ideation`、`implement-proposal`、`propose-and-build`は、ドラフトの手順を参照します。ドラフトを作ると、レビューの開始前に提案へPR番号を書き込めます。
- **導入の順序。** この変更のレビュー中、ルールセットは`claude review`を含みません。変更をマージし、`gh pr ready`の後の成功が同じコミットの失敗を置き換えることをドラフトのPRで確かめてから、メンテナーが必須チェックに加えます。それまで、このチェックはマージを止めません。
- **制限。** フォークからのPRには秘匿情報が渡らず、認証情報のない環境ではレビューが始まりません。どちらの場合も、変更前と同じく、人がドラフトを解除したPRのチェックは、レビューなしで合格します。ドラフトとボットのイベントは、この場合も失敗します。

## 検討した代替案

- **ドラフトとボットをスキップする。** スキップされたチェックは合格になります。そのため、レビューが登録される前や、ボットがドラフトを解除したときに、レビューなしでマージできます。ドラフトのチェックが赤くなることは、この2つの隙間を塞ぐための代償です。
- **プッシュのたびにレビューする。** `synchronize`トリガーを使えば、チェックは先頭コミットに付きます。しかし、途中のプッシュのたびにトークンを使い、レビューが自分の指摘への修正に再び指摘することもあります。
- **必須チェックから外す。** レビューが動く前にPRをマージできてしまいます。
- **フックで`--draft`とセルフレビューを強制する。** フックは、`gh`コマンド以外で作ったりドラフトを解除したりしたPRを見逃します。まずは、すべての経路に及ぶ共通の指示から始めます。
