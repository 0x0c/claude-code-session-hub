## はじめに

Gitがコミットを記録する前に、秘匿情報が含まれていないかを検査します。リポジトリで管理するGitフックが、秘匿情報スキャナーのgitleaksを、ステージした変更とコミットメッセージに対して実行します。検出するとコミットを止めます。ローカルのフックは迂回できるため、継続的インテグレーション（CI）のジョブでも履歴を検査します。

## 動機

このリポジトリは公開されており、コミットの多くはエージェントが作ります。テストデータやコミットメッセージに貼ったキーは、プッシュした時点で公開されます。後のコミットで消しても、公開は取り消せません。現在、コミット前に秘匿情報を検査する仕組みはありません。

この変更が入ると、ClaudeのOAuthトークンをステージしたコミットは失敗します。メッセージはファイルと行を示し、トークン自体は表示しません。

## 詳細設計

### フック

フックは`.githooks/`に置きます。開発者は、クローンごとに一度`make setup`を実行して有効にします（[セットアップ](#セットアップ)で説明します）。パスは相対なので、フックを含むブランチのワークツリーすべてに効きます。

| フック | 検査の対象 |
|---|---|
| `pre-commit` | ステージした変更 |
| `pre-merge-commit` | 競合のないマージの結果（Gitは`pre-commit`を実行しない） |
| `commit-msg` | コミットメッセージ |

- **検出したとき：** フックは0以外で終了します。gitleaksは出力の中の秘匿情報を伏せます。
- **gitleaksがないとき：** コミットを止め、`make setup`を案内します。
- **緊急のとき：** `git commit --no-verify`でフックを飛ばせます。CIのジョブは秘匿情報を報告します。

### セットアップ

`make setup`の1コマンドで、クローンは作業を始められる状態になります。このコマンドは`scripts/setup.sh`を実行します。何度実行しても問題ありません。

1. `python3`、`curl`、`tar`があることを確かめます。
2. `core.hooksPath`に別のフォルダーが設定されていれば、中止します。置き換えるとそのフックが無効になるためです。
3. バージョンを固定したgitleaksを、全ワークツリーが共有するGitフォルダーにダウンロードします。スクリプトに書いたチェックサムと一致したときだけ使います。対応するのはmacOSとLinux（x64とarm64）です。
4. `core.hooksPath`を`.githooks`に設定します。

セットアップを飛ばしたまま作業が進まないよう、次の場所で確かめます。

| 場所 | 動作 |
|---|---|
| Claude Codeのセッション開始 | `.claude/settings.json`がセットアップを実行し、失敗すれば理由をコンテキストに示す |
| Claude Codeの編集ツール | 完了するまで、PreToolUseフックが編集を止める |
| `scripts/check.sh` | ゲートが失敗する。`make check`は先にセットアップを実行する |

編集を止めるのはこのリポジトリだけです。`make setup`を実行できるよう、シェルのコマンドは止めません。シェルを使った変更は、ゲートとCIのジョブで確かめます。ネットワークがなければ初回のセットアップは失敗し、編集は止まったままです。

### ルール

`.gitleaks.toml`は、gitleaksの組み込みルールに2つのルールを加えます。

- `anthropic-api-key`は、組み込みルールが見逃すOAuthのアクセストークンと更新トークン（`sk-ant-oat01-`、`sk-ant-ort01-`）も検出します。
- `hub-token`は、`HUB_TOKEN`の後に16文字以上の値を直接書いた箇所を検出します。シェル変数や短い仮の値は検出しません。

許可リストの各項目は、ルールとファイルを1つずつ指定します。誤検知への対応で、他の箇所のルールが無効になることはありません。最初の項目は、`scripts/design_system.lock.json`の内容ハッシュです。

### 履歴の検査

`scripts/check_secrets.sh`は、`HEAD`から到達できる全コミットを検査します。マージコミット自体の変更も含みます。ゲート（`scripts/check.sh`）はこのスクリプトを実行します。`Tests`ワークフローは、履歴の浅いチェックアウトで`make check`を実行します。全履歴を取得する`secret-scan`ワークフローは、プルリクエストと`main`で`make setup`と同じスクリプトを実行します。

ジョブが報告するのはプッシュの後です。フックを迂回した秘匿情報は失効させる必要があります。

## 検討した代替案

- **Pythonで独自のスキャナーを書く。** インストールは要りませんが、各サービスのパターンを自分たちで保守することになります。
- **gitleaksがなければ警告してコミットを通す。** 警告は見落としやすく、セットアップは作業するどの環境にもgitleaksを入れます。
- **gitleaksをHomebrewで入れる。** クラウドのサンドボックスにHomebrewはなく、バージョンもそろいません。
- **文書でセットアップを求めるだけにする。** 飛ばされても気づけません。
- **pre-commitフレームワークを使う。** 依存のないこのリポジトリに、Pythonの依存が加わります。
- **履歴ではなく作業フォルダーを検査する。** 後のコミットで消した秘匿情報を見逃します。無視対象のファイルや他のワークツリーも読んでしまいます。
- **Claude Codeのhookを使う。** 人が作るコミットを検査できません。
