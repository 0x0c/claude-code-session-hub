## はじめに

セッションがプルリクエスト（PR）を持つとき、ダッシュボードのカードからそのPRを開けるようにします。リンクはhookがトランスクリプトから読み取るので、エージェントもユーザーも報告せずに済みます。

## 動機

ダッシュボードを見る人は、セッションが扱うPRをよく開きます。しかし、カードに番号が出るのは、セッションが`session-hub pr`で報告したときだけです。その番号も単なる文字列です。コマンドを実行しないセッションには、何も出ません。

この変更の後は、PRを開いたセッションのカードに、次の更新で`PR#45`が出ます。遅くとも、実行中のターンの終了時には出ます。番号をクリックすると、PRが新しいタブで開きます。

## 詳細設計

- **リンクの読み取り。** Claude Codeは、`prNumber`と`prUrl`を持つ`pr-link`レコードをトランスクリプトに書きます。`session_hub/pr_link.py`は最後のレコードを使います。ファイルがないときや読めないときは、何も返しません。
- **送信。** `deliver`は、セッション自身が送る更新に、省略可能なフィールド`pr_link: {number, url}`を加えます。親による更新にはリンクを付けません。
- **検証。** ハブが受け入れるリンクは、番号が正の整数で、Uniform Resource Locator（URL）が`http://`または`https://`で始まる500文字以内のものです。それ以外のリンクは捨て、更新の残りを記録します。
- **畳み込み。** ステータスレコードはリンクを`pr_link`に保持し、現在のPRを`pr`に保持します。リンクは毎回の更新に付くため、前回のリンクと異なるときだけ反映します。変化したリンクと`session-hub pr`の報告では、新しいほうを使います。PRの番号またはURLが変わると、古いPRの継続的インテグレーション（CI）の結果などを消します。リンクと同じ番号をURLなしで報告したときは、リンクのURLを補います。
- **表示。** `pr.url`がWebのアドレスなら、カードのPR表示をリンクにします。リンクをクリックしても、カードは選択されません。URLなしで報告されたPRは、文字列のままです。
- **互換性。** 古いハブは、追加のフィールドを保存して無視します。この変更より前のイベントの畳み込みは、別のPRの報告が古いPRの情報を消す点を除き、従来どおりです。

どのモデルのコンテキストにもテキストを追加しません。

## 検討した代替案

- **エージェントに`--url`を渡してもらう。** トランスクリプトにある事実のためにトークンを使います。報告を忘れるとリンクも出ません。このオプションは引き続き使えます。
- **リンクが現れたときに`pr`イベントを別に送る。** 重複を避けるには、送信側が状態を持つ必要があります。イベントが失われると、リンクも失われます。
- **セッションが開いたすべてのPRを表示する。** レビューゲートは、1つのセッションにつき1つのPRを判定します。一覧にするには、ステータスレコードをより広く変える必要があります。
