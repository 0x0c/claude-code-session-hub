## はじめに

`scripts/design_system.py`を追加します。このスクリプトは、デザインシステムのページに何を公開するかを決めます。ページはClaudeのアーティファクトで、ダッシュボードのデザイントークンと部品を説明します。スクリプトはべき等です。すでに一致しているページを同期しても、何も公開しません。

## 動機

ページは、エージェントが使い捨てのスクリプトで作りました。数時間のうちにダッシュボードから遅れ、リポジトリにはページを作り直す手段も、古いファイルを見分ける手段もありませんでした。作り直しが、ページ上で人が加えた変更を上書きするおそれもありました。

この変更が入ると、続けて2回目の同期は「in step: nothing to publish」と報告します。また、指示がないかぎり、人の編集を置き換えません。

## 詳細設計

値とスタイルの規則は`session_hub/templates/dashboard.html`から読みます。文章と部品のプレビューは`scripts/design_system_content.py`から読みます。

| コマンド | 動作 |
|---|---|
| `build --out <dir>` | 生成するファイルをすべて書き出す |
| `plan --live <dir> --out <dir>` | 生成結果とページの最新の写しを比べ、公開するファイルと`publish.json`を書き出す |
| `record --live <dir>` | ページが生成結果と一致することを確認し、ロックを書く |

スクリプトはアーティファクトに接続できません。そのため、エージェントがページを写しのフォルダーに読み込み、`publish.json`の内容を公開します。公開後にもう一度読み込み、`record`を実行します。

`scripts/design_system.lock.json`は、最後に公開した各ファイルのハッシュを持ちます。計画では、生成結果・ページ・ロックの3つを比べます。

| ページの状態 | 計画 |
|---|---|
| 生成結果と一致 | 何もしない |
| 生成結果と異なり、ロックと一致 | 更新 |
| 生成結果ともロックとも異なる | 競合（人が編集） |
| ロックにあるファイルがない | 競合（人が削除） |
| ロックにないファイルがない | 追加 |
| 生成しなくなったファイルがロックにあり、ページにも残る | 削除 |

競合があると、計画は終了コード2で止まります。`--overwrite <path>`を付けると、リポジトリの内容を優先します。こちらが公開していないファイルには触れません。ページの索引は公開するときだけ変わり、`lastChange`以外のキーを保ちます。

生成結果は時刻を含みません。生成は次の3つの場合にエラーで止まります。トークンと説明が対応しない場合、プレビューがダッシュボードにないクラスを使う場合、スタイルシートの形が変わった場合です。テストが生成を実行するので、同期を壊すダッシュボードの変更は検査で失敗します。

## 検討した代替案

- **同期のたびにページ全体を上書きする。** 単純ですが、ページ上の編集を失い、毎回新しい版を作ります。
- **ロックとだけ比べる。** ページの写しは不要になりますが、人の編集を検出できません。
- **生成したファイルをリポジトリに置く。** スタイルシートの変更がレビューで二重になります。ロックなら、1ファイル1行で同じことがわかります。
