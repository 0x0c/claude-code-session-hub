## はじめに

どのセッションがどのセッションを起動したかを、セッション一覧に表示します。親子が一覧の同じグループにあれば、子のカードを親の下に字下げし、線で結びます。別のグループにあれば、子のカードに親へのリンクを表示します。子が親を報告しないときは、ハブが自分で親を見つけます。

## 動機

ステータスには以前から`parent_id`フィールドがありますが、ダッシュボードのどこにも表示していません。親子の組をいくつも動かすユーザーには1つの平らな一覧が見えるだけで、どれがどれを起動したかを覚えておく必要があります。

このフィールドには漏れもあります。記録する手段が`session-hub start --parent`しかないためです。作者のハブでは、Claudeデスクトップアプリが別のセッションから起動したセッションが4件あり、そのうち1件に親の記録がありませんでした。

この変更が入ると、デスクトップアプリが起動した子は、親を名乗らなくても数秒で親のカードの下に表示されます。

## 詳細設計

### 親を見つける

ハブは3つの情報源から親を決めます。強い順に並べます。

| 情報源（`parent_source`） | 出どころ | イベントのフィールド |
|---|---|---|
| `reported` | `session-hub start --parent <id>` | `parent_id` |
| `environment` | `HUB_PARENT_SESSION_ID`。`start`とStop hookが送ります | `parent_hint` |
| `desktop` | デスクトップアプリのセッションファイルの`spawnedFrom.sessionId` | `parent`イベントの`parent_hint` |

- **畳み込み**: ステータスは`parent_id`と、新しいフィールド`parent_source`を持ちます。届いた順序にかかわらず、弱い情報源は強い情報源を上書きしません。同じ情報源では最後の値が有効です。自分自身を親とするセッションには親を設定しません。形式の正しくない`parent_hint`は捨てます。自動の値のせいで、ハブが更新を拒否してはならないためです。
- **環境変数**: `start`は、実行中のセッション自身についてだけ値を送ります。環境変数からは、ほかのセッションのことがわからないためです。
- **デスクトップアプリ**: ハブは、既存の5秒ごとの走査で`sessionId`と`spawnedFrom`を読みます。アプリの識別子（ID）をClaude CodeのセッションIDに置き換え、`parent`イベントを`events/<session_id>@desktop.jsonl`に記録します。記録するのは、セッションに親がなく、親のセッションをハブが知っているときです。アプリのファイルどうしが食い違うときは記録しません。
- **記録だけのイベント**: `parent`イベントは状態もheartbeatも変えません。セッションを新しく作ることも、アーカイブを解除することもありません。以前のバージョンは、知らない種類としてこのイベントを読み飛ばします。
- **プロンプト**: `prompts/child-append-system-prompt.md`のstartコマンドに`--parent {{PARENT_SESSION_ID}}`を加えます。`claude -p`の子には、ほかの情報源がないためです。

### 親子を表示する

- **同じグループ**: 各カード一覧に親子がそろっていれば、子を親の下に置きます。何階層でも、子を字下げして線で親と結びます。親子の組は、最も新しく更新された一員の位置に並びます。子は最終更新の順に並びます。
- **別のグループ**: グループの分け方は変えないので、要対応の子は一覧の先頭に残ります。子のカードには「↳ 親のタイトル」を表示します。クリックすると、親を隠している折りたたみを開き、親を選択してその位置までスクロールします。
- **親のカード**: ハブにある直接の子の数を、グループを問わず数えて表示します。
- **未知の親と循環**: ハブが知らない親については何も表示しません。親の関係が循環するセッションは独立して並べ、循環の外にいる子孫はその下に置きます。
- **グリッド表示**: 親子の組はグリッドの1列に積みます。親子の組を含む一覧のカードは、それぞれの高さを保ちます。隣のカードを引き伸ばすと、ほとんどが余白になるためです。
- **タイムライン**: `parent`イベントは、親のタイトルを添えて「親の検出」と表示します。

## 検討した代替案

- **状態を問わず、すべての子を親の下に移す。** 要対応の子が一覧の先頭から外れ、折りたたんだグループに隠れることがあります。
- **完了した子だけを親の下に移す。** 「作業中・待機」の見出しの下に、完了したセッションが混ざります。
- **字下げせず、リンクだけを表示する。** 変更は小さくなりますが、親子の組の形が読み取れません。
- **報告された親だけを使う。** 親を報告しなかったセッションは、平らに並んだままです。
- **イベントを記録せず、スナップショットを作るときにアプリの親を計算する。** イベントストアが唯一の正しい情報源ではなくなり、アプリのファイルとともに関係も消えます。
