## はじめに

1つのサブセッションについて、保存済みのメッセージをすべて削除する手段を追加します。ユーザーはダッシュボードの **セッションを削除** ボタンか、ターミナルの `session-hub delete <session_id>` でセッションを消せます。ハブはそのセッションのイベントファイルをストアから物理的に削除し、スナップショットを作り直して、開いているすべてのダッシュボードからそのセッションを即座に消します。

ストアの形式は今のままです。JavaScript Object Notation（JSON）Lines のファイルを書き手ごとに1つ持ち、追記のみで書き込みます。削除は「追記のみ」に対する唯一の明示的な例外で、セッション単位でしか働きません。そのため、他のセッションのイベントには一切触れません。

## 動機

ハブは受信したメッセージをすでにすべて永続化しています。メッセージは1件ごとに `<store>/events/<session_id>.jsonl` の1行になり、ハブは再起動後にこれらのファイルから状態を作り直します。一方で、行を消す手段はありません。そのため、完了・失敗・テストのセッションがいつまでも溜まり続けます。

- セッション一覧が伸び続け、対応が必要なセッションが古いセッションに埋もれます。
- デモや試行のセッションが、本来の作業と混ざったまま残ります。
- 今は、ハブを止めてファイルを手で消すしか片付ける方法がありません。そのためにはストアの構成と、親が書く `@parent` ファイルの存在を知っている必要があります。

この変更が入ると、完了したセッションで **セッションを削除** をクリックすれば、開いているすべてのダッシュボードで、そのセッションがセッション一覧・タイムライン・すべてのコレクションから1秒以内に消えます。ファイルも `<store>/events/` からなくなり、ハブを再起動してもそのセッションは戻りません。

## 詳細設計

### ストア

`EventStore.delete_session(session_id) -> int` は、セッションのファイルをすべて削除し、それらのファイルにあったイベント数を返します。

1. `append` と同じ検査（`SAFE_ID`、`@` を含まない）で `session_id` を検証します。
2. セッションのファイルを集めます。対象は `<session_id>.jsonl` と、すべての `<session_id>@<writer>.jsonl` です。
3. ファイルごとに、`append` と同じ排他ファイルロックを取り、有効なイベントを数え、ロックを保持したままファイルを削除（unlink）します。
4. 合計数を返します。`0` は、ストアにそのセッションがなかったことを意味します。

削除と書き手の競合は1通りだけあります。書き手がファイルを開いてからロックを待つ間に、`delete_session` がそのファイルを削除する場合です。書き手は名前のなくなったファイルに追記することになり、イベントが消えてしまいます。この隙間を塞ぐため、`append` はロックを取った後、開いたファイルにまだ名前があるか（`os.fstat(...).st_nlink > 0`）を確かめます。名前がなければパスを開き直し、新しいファイルを作ります。したがって、削除後も報告を続けるセッションは新しいイベントだけを持って再び現れ、イベントが黙って失われることはありません。

### ハブサーバー

`Hub.delete_session(session_id) -> int` は、ハブの書き込みロックの中でストアのメソッドを呼び、続けて `publish()` を呼びます。`publish()` はすでに新旧のスナップショットを比べ、消えたイベントの識別子（ID） を `update` メッセージの `removed` フィールドで配信しています。新しいセッション一覧とコレクションも同じメッセージで届きます。コレクションのシンクは、他の変更のときと同じく書き直されます。

この操作を新しいエンドポイントで公開します。

```
DELETE /api/sessions/<session_id>
  200 {"session_id": "...", "deleted": <event count>}
  400 {"error": "..."}            invalid session id
  401 {"error": "unauthorized"}   same token rule as the other endpoints
  404 {"error": "no such session"}
```

`DELETE` メソッドを選んだのは意図的です。別オリジンの Web ページは、Cross-Origin Resource Sharing（CORS）のプリフライトリクエストなしにクロスオリジンの `DELETE` を送れません。そしてハブはプリフライトに応答しません。そのため、ユーザーがたまたま開いた悪意あるページがループバックのハブ経由でセッションを消すことはできません。単純なコンテンツタイプの `POST` なら、ハブに届いてしまいます。

### コマンドラインインターフェース（CLI）

`session-hub delete <session_id>` は1つのセッションを削除し、`deleted <session_id> (<n> events)` と表示します。経路は報告系のコマンドと同じ方法で選びます。

1. `HUB_URL` が設定され、`--store` が指定されていなければ、ハブに `DELETE /api/sessions/<session_id>` を送ります。ダッシュボードは即座に更新されます。
2. ハブに届かず、ストアが設定されていれば（`HUB_STORE` または `--store`）、ストアから直接削除します。ハブは次の作り直し（次のメッセージ、または30秒ごとの再確認）で変更を拾います。
3. `HUB_URL` がなければ、ストアから直接削除します。

Git で共有するストアを直接削除した後は、既存の `sync` を実行します。`sync` は削除されたファイルをステージし（`git add events` は削除もステージします）、プッシュします。セッションが存在しなければ、コマンドは終了ステータス1で終わります。確認の質問はしません。エージェントやスクリプトが コマンドラインインターフェース（CLI）を非対話で実行するためで、明示的なセッション ID の指定が確認の代わりです。

### ダッシュボード

セッションが選択されていて、ページがライブ表示のとき（`session-hub export` による静的エクスポートではないとき）、タイムラインの見出しの右端に **セッションを削除** ボタンを表示します。各セッションカードではなく見出しに置くのは、カード自体がボタンだからです。ボタンを入れ子にすると、アクセシビリティが損なわれます。

1. クリックすると確認ダイアログを開きます。ダイアログはセッション名とメッセージ数を示し、削除は取り消せないと伝えます。
2. 確認されると、ページは `DELETE api/sessions/<session_id>` を送り、選択を解除します。
3. 続いて届く `update` メッセージで、そのセッションのイベント・カード・コレクションの項目が消えます。
4. 失敗したときは、サーバーのエラーを警告ダイアログで示し、何も消しません。

Server-Sent Events（SSE）が失敗したときに使うポーリングも、削除を把握できるようにします。新しいスナップショットにないイベントの ID を計算し、`removed` として渡します。ボタンのラベルとダイアログの文言は、英語と日本語で `MESSAGES` テーブルに置きます。

### 変わらないもの

- イベントの形式、ファイルの構成、既存のエンドポイントは変わりません。したがって、古いハブや CLI も、削除を経たストアを問題なく読めます。
- イベント1件単位の削除と、論理削除（「削除済み」を表すイベント）は対象外です。
- 配布するスキルではこのコマンドに触れません。削除は人間が判断する片付けで、親の定型作業の一部ではありません。また、スキルに1行足すと、読み込むたびにトークンがかかります。

## 検討した代替案

- **ストアを SQLite に移す。** SQLite なら削除は1文で済み、規模にも強くなります。しかしバイナリの1ファイルになるため、書き手ごとの追記型テキストファイルに頼っている Git でのストア共有が壊れます。削除にデータベースは要らないので、ファイルのままにします。
- **目印のイベントによる論理削除。** `deleted` イベントを追記すればストアは追記のみのままですが、データはディスクに残り、読み手はすべてそれを読み飛ばす必要があります。ユーザーはデータ自体を消すことを求めています。
- **メッセージを1件ずつ削除する。** イベントを1件消すと、セッションの状態が思わぬ形に変わります（質問のない回答が残るなど）。また、ファイルをその場で書き換える必要があります。セッション単位の削除なら、その危険なしに片付けの要望を満たせます。
- **各セッションカードに削除ボタンを置く。** カードはすでにセッションを選ぶボタンです。ボタンを入れ子にすると、キーボードやスクリーンリーダーでの操作が壊れます。
