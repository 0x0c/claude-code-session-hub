## はじめに

ダッシュボードに、デザイントークンを1式用意します。デザイントークンは、色・文字・余白・角丸に名前を付けたCascading Style Sheets（CSS）のカスタムプロパティです。`session_hub/templates/dashboard.html`のすべての規則はトークンから値を取り、直書きの値はテストが拒否します。

同じ変更で、セッションのグループ見出し（「要対応」「作業中・待機」「完了」）を塗りのあるバッジにします。グループ見出しは、トークンで組む最初の部品です。

## 動機

ダッシュボードの色には名前がありますが、寸法はすべて直書きです。文字サイズの12pxは14の規則に現れます。余白は14種類の値を使い、1ピクセルしか違わない値も混ざっています。そのため、新しい部品が従うべき尺度がありません。グループ見出しがその例です。11pxの補助色なので、下に並ぶカードに埋もれて見つけにくくなっています。

この変更が入ると、グループ見出しがカードと見分けやすくなります。また、文字サイズ・余白・角丸・色を直書きした規則があると、`scripts/check.sh`が失敗します。

## 詳細設計

`:root`ブロックがすべてのトークンを持ちます。

| トークン | 用途 |
|---|---|
| `--bg`, `--panel`, `--ink`, `--muted`, `--line`, `--hover`, `--accent`, `--flash` | 面・文字・罫線・強調 |
| `--s-*` | セッションの状態 |
| `--g-action`, `--g-active`, `--g-done`, `--g-archived` | グループ見出しの塗り（両テーマ共通） |
| `--on-fill` | 塗りの上の文字 |
| `--shade` | グリッドの詳細パネルが落とす影 |
| `--font-sans`, `--fs-*` | 書体と5つのサイズ（11・12・13・14・16px） |
| `--fw-normal`, `--fw-strong` | 太さ400と600 |
| `--space-*` | 1・2・4・6・8・10・12・14・16・24px |
| `--radius-*` | 3・4・6・8・10pxとピル形 |

既存の色は値を変えません。尺度から外れた値は近い段階に移します。余白は3pxを4px、5pxを6px、7pxを8pxにし、2pxの角丸は3pxにします。例外はタイムラインの印です。文字の行の中央にそろえるため、余白を5pxから4pxにします。列の幅・アイコンの大きさ・スイムレーンの図のように、リズムではなく配置を表す寸法は直書きのまま残します。`0`と`auto`、円を表す50%の角丸、`calc()`でトークンに足す配置の寸法も直書きのままです。

グループ見出しは、12px・太さ600のバッジです。`--g-*`の塗りに`--on-fill`の文字を載せます。文字は、下に並ぶ14pxのセッション名より小さく保ちます。塗りと白文字のコントラストは、両テーマで4.5:1以上です。

テストはスタイルシートを読み、次の4つの規則を確認します。

- トークンのブロックの外で、文字サイズ・太さ・余白・角丸・色を直書きしないこと。
- 規則が使うカスタムプロパティがすべて定義済みであること。
- 状態のグループがすべて塗りを持つこと。
- 2つのダークのブロックが、同じトークンを同じ値で定義すること。

## 検討した代替案

- **すべての寸法をピクセル単位で保つ。** 尺度に3px・5px・7pxの段階が必要になります。どの部品にも要らない段階なので、尺度が指針になりません。
- **スタイルシートを別ファイルにする、またはCSSのビルドを加える。** ダッシュボードは1つの自己完結したファイルで、`session-hub export`がその形に依存しています。
- **状態バッジのコントラストも直す。** 一部の`--s-*`の塗りでは、白文字のコントラストが4.5:1を下回ります。多くはダークテーマです。直すと意味を担う色が変わるため、別の提案で扱います。
